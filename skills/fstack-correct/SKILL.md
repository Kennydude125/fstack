# Correct

Find repeated financial research or tooling mistakes and prevent recurrence at the highest effective level.

1. Read the scoped corrections, failed experiments, review findings, model revisions and existing controls. A recurring class needs repeated evidence; one bad market outcome alone is not a process defect.
2. Prefer eliminating the mistake through one source of truth and clear ownership. Then consider data types/schema boundaries, a useful validation error, and an observable regression test. Write prose rules last for judgment calls.
3. Reproduce a real past mistake and prove the new check rejects it. Run the same command locally and in CI where available. Do not weaken checks to accommodate a misleading report.
4. Keep a concise rule-to-enforcement table in the appropriate project instructions. Remove redundant reminders once structure enforces the rule.
5. Report each class, evidence, chosen enforcement, demonstrated failure/pass and remaining limit. Scope changes, publication and external writes follow the host's authority rules.
