# Authoring a skill

1. Use the host skill creator on the actual financial workflow. Keep the coordinator responsible for voice and scope.
2. Validate frontmatter, namespacing, local references, source attribution and cross-skill links. Preserve upstream treatment in the adaptation registry.
3. Run behavioral cases for structural changes, including failures and missing capabilities. Subjective prose changes need appropriate review rather than mirrored wording tests.
4. Deliver the skill, concrete changes and validation evidence. Code/skill publication follows the user's actual authorization; a financial research answer does not require a PR.

See the [main mode](../SKILL.md) for linked peer skills and the [finance contract](../../../references/finance-contract.md) for shared artifact and authority rules.
