# Eval

1. Define the behavior under comparison and write 3–6 observable criteria for the judge only. Separate research-process quality from forecasting success.
2. Prepare isolated environments under neutral project-shaped names. Candidates must not see eval, test, judge, experiment, rubric, score, compare, benchmark, candidate or arena in their visible paths or prompt.
3. Give every candidate the same organic user request and permitted raw evidence. Do not disclose the expected result, competitor, model label or hidden rubric. Do not ask candidates to narrate which skill they followed.
4. Run fresh independent candidates with the configured models and isolated outputs. Preserve input identity and actual tool activity.
5. After completion use one blinded judge from a different available family where possible. It sees neutral output labels and one common rubric. If unavailable, record the missing cross-family gate and report the review that actually ran.
6. Audit actual file/tool activity and outputs rather than self-report. Use only the active authorized transcript; if the host cannot expose it, state that the trace audit is incomplete.
7. Read all outputs, reconcile disagreement, and report per-case evidence, failures, gaps and a promotion recommendation. Do not call a tiny behavioral comparison a statistical investment win rate.
