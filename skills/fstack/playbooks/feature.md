# Feature

1. Restate the user's research goal and expected artifact. Use how, and why when revising an existing decision or assumption.
2. Name the data/model contract first: instruments, units, observation/publication dates, cutoff, inputs, outputs and falsification conditions. Use architect when consequential choices cross boundaries.
3. Write a throughput checkpoint with expected units, parallel seams, shared-state ownership and blockers. Build verification and baseline before new calculations.
4. Delegate bounded implementation or research units to fresh workers. Give one owner per artifact, isolated outputs and exact input identity. Execute independent work concurrently within host limits.
5. Check actual results in dependency order. Use a different author and verifier for formal deliverables. Run interrogate on contested or consequential artifacts.
6. Finalize through Shipping. Deliver a sourced research memo, valuation or strategy specification with limitations, not a promise of future returns.
