# Prototype

1. State the empirical question and the observation that will settle it. Use a prototype only for a discoverable feasibility or design choice, not a user preference.
2. Build the smallest isolated experiment using synthetic or authorized fixed data. Bound time, scope and side effects before execution.
3. Inspect actual output and compare alternatives where needed. A favorable illustrative backtest does not validate an edge.
4. Report the design/feasibility decision, evidence, discarded alternatives and limits. Keep useful evidence; promote no prototype code or investment conclusion without its proper verification path.
