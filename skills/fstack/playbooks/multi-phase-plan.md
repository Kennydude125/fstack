# Multi-phase plan

1. Ground the user's objective, current artifacts and actual constraints with how and why where needed. Define measurable deliverables and genuine preference decisions.
2. Order independently verifiable phases by dependency and riskiest unknown. Put data contracts, baseline and verification before the work they assess.
3. For each phase name owner, inputs, outputs, prerequisite, evidence gate, independent review and stopping condition. Distinguish missing-data, failed and inconclusive outcomes.
4. Use finance-relevant verification lanes: provenance/cutoff, calculation correctness, experiment isolation, assumptions/costs, source-backed thesis review and report fidelity. Add UI/software checks only when that phase actually changes them.
5. Present tradeoffs and decisions before implementation when requested or when the host is in planning mode. Do not copy an engineering template's ten GUI lanes into a company report.
6. During execution keep actual status and evidence pointers current, and finalize only gates tied to current artifacts. Plan linting cannot authenticate its own checkboxes or prove a trading edge.
